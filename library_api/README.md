# Библиотека — API-контракт

OpenAPI 3.1 спецификация для сервиса «Библиотека»: книги, читатели и выдачи.

## Состав репозитория

| Файл | Что внутри |
|---|---|

| `REVIEW.md` | Саморевью по чек-листу |
| `README.md` | Этот файл |

## Что описано в контракте

- **Books** — CRUD (список, создание, чтение, полное и частичное обновление, удаление).
- **Readers** — CRUD.
- **Loans** — создание, список, чтение по id, возврат через `POST /loans/{id}/return`.
- **Фильтры, сортировка, пагинация** — на всех коллекциях.
- **Единый `ErrorResponse`** — шесть кодов ошибок: `INVALID_REQUEST`, `NOT_FOUND`, `VALIDATION_ERROR`, `CONFLICT`, `BUSINESS_RULE_VIOLATION`, `IDEMPOTENCY_MISMATCH`.
- **Idempotency-Key** — обязательный заголовок на `POST /loans`, TTL 24 часа.

## Бизнес-правила

1. **Выдача только при наличии копий.** Если `available_copies == 0` — операция отклоняется с 409 `BUSINESS_RULE_VIOLATION`.
2. **Не более 5 активных выдач на читателя.** Активная выдача — та, у которой `returned_at == null`. Превышение — 409 `BUSINESS_RULE_VIOLATION`.
3. **Возврат книги — через `POST /loans/{id}/return`.** Не через `DELETE`, не через `PATCH`. Тела у запроса нет, сервер сам ставит `returned_at = now()`.
4. **Просроченные выдачи.** Фильтр `GET /loans?status=overdue` возвращает выдачи, у которых `due_date < now()` и `returned_at == null`.
5. **Нельзя удалить книгу или читателя с активными выдачами.** Если есть хотя бы одна активная выдача, `DELETE /books/{id}` или `DELETE /readers/{id}` возвращает 409 `BUSINESS_RULE_VIOLATION`.
6. **`due_date` новой выдачи — позже текущей даты.** Иначе 422 `VALIDATION_ERROR` с указанием поля.
7. **`available_copies` вычисляет сервер.** Поле = `total_copies` минус число активных выдач. Клиент его не передаёт и не может изменить напрямую.
8. `registered_at`, `loaned_at` вычисляет сервер как now()

## Идемпотентность

`POST /loans` требует заголовок `Idempotency-Key` (UUID). Семантика:

| Сценарий | Поведение |
|---|---|
| Повторный запрос с **тем же** ключом и **тем же** телом | Возвращается ранее сохранённый ответ (полный replay). Новая выдача не создаётся. |
| Тот же ключ, но **другое** тело | 409 `IDEMPOTENCY_MISMATCH`. |
| Конкурентные повторы (два запроса одновременно с одним ключом) | Создаётся только одна выдача. Второй запрос либо ждёт, либо получает тот же результат. |
| Тот же ключ через **24 часа** | Считается новым. |

Ключ хранится 24 часа с момента первого запроса. После истечения срока тот же ключ обрабатывается как новый.

## Авторизация

Все изменяющие операции (`POST`, `PUT`, `PATCH`, `DELETE`) требуют Bearer JWT.

**Формат заголовка:** `Authorization: Bearer <token>`

Схема описана в `components/securitySchemes/BearerAuth`:

- Тип: `http`
- Схема: `bearer`
- Формат токена: `JWT`

Публичные операции (без авторизации): `GET /books`, `GET /books/{id}`, `GET /readers`, `GET /readers/{id}`, `GET /loans`, `GET /loans/{id}`.

## Совместимость v1 → v2

| Изменение | Breaking? | Почему                                    |
|---|-----------|-------------------------------------------|
| Добавить опциональное поле в response | нет       | Старый клиент проигнорирует               |
| Добавить обязательное поле в response | да        | При строгой валидации                     |
| Добавить опциональный query-параметр | нет       | Старые запросы продолжат работать         |
| Добавить обязательный query-параметр | да        | Старые запросы станут невалидными         |
| Удалить поле из response | да        | Клиент мог его читать                     |
| Переименовать поле | да        | Клиент не найдёт старое имя               |
| Сменить тип поля | да        | Клиент не сможет распарсить               |
| Расширить enum новым значением | нет       | Клиента нужно предупредить о новом значении |
| Сузить enum (убрать значение) | да        | Клиент мог использовать удалённое значение |
| Изменить URL | да        | Клиент ходит по старому URL               |
| Добавить новый endpoint | нет       | Старые клиенты его не используют          |
| Удалить endpoint | да        | Клиенты, использующие его, сломаются      |

## Устаревшие поля

Поле `full_name` в схеме `Reader` помечено как `deprecated` и будет удалено в v2. 
Вместо него будут поля `first_name` и `last_name`
